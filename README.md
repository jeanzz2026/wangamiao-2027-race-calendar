# 王阿喵 · 2027 参赛训练计划

一个纯静态网页应用，用于管理王阿喵的 **2027 年比赛训练计划、基础训练库与打卡记录**，部署在 GitHub Pages。

🌐 在线地址：https://jeanzz2026.github.io/wangamiao-2027-race-calendar/

---

## 功能介绍

应用顶部为三个标签页：**参赛计划（RACE PLAN）** / **训练计划（TRAINING PLAN）** / **Takeaway（TAKEAWAY）**。

### 1. 参赛计划 · 赛事日历排布
- 在 12 个月日历上拖拽排布 2027 年目标赛事（参赛日期、地点、类型、报名渠道与时间提示等）。
- 桌面端拖拽赛事卡片换月；手机端用卡片详情里的「安排到」菜单换月。
- 顶部可搜索赛事、按 **首选 / UTMB / 全马** 等筛选；右侧详情面板含官方报名渠道与提示。
- 登录后可「**恢复原计划**」一键回退赛事月份安排。

### 2. 训练计划 · 基础训练库
- 内置常用训练动作示例，按类型区分：**路跑 / 越野 / 通用 / 交叉训练 / 游泳 / 骑行 / 比赛**。
- 可自定义增删训练类型（**新建 / 编辑 / 删除**），指定配色、默认时长与说明。
- 从训练库**一键「添加」到某天**，或拖拽到日历任意日期；添加后可单独编辑该次训练的时长 / 备注，**不影响训练库原始内容**。
- 训练库可「**保存为默认库**」固化当前版本，随时「**恢复默认库**」回到出厂或你保存的快照，已排进日历的训练不受影响。
- **周视图 / 月视图**切换（记忆上次选择）；按类型筛选训练库列表与日历。

### 3. Takeaway · 执行记录
- 独立「Takeaway」模式，记录每天**实际训练执行情况**，与「训练计划」解耦：在 Takeaway 页编辑实际内容 / 完成度 / 备注**不影响原计划**；计划变更会同步默认值，但保留你的编辑。
- 点击训练卡片或进度条打开记录弹窗：
  - **实际训练内容**：一行，可从基础训练库下拉选择（自动带入配色 / 说明 / 时长），也可自由输入。
  - **完成度（0–100%）**：过去默认 100%、今天及以后默认 0%，可手动修改；日期旁圆点反映当天平均完成度（100% 绿 → 0% 深红），未来日期不显示。
  - **Comments**：记录当天感受、心率区间、配速、可复用经验等。
- **非训练日也可补记**：点「＋ 添加记录」手动添加独立记录（无对应计划）。
- 统计面板：平均完成度（已完成 X / 总 Y 次）、**本周 / 本月完成度**（随视图切换）、分类完成度。
- 同日非恢复类训练超过 2 项时弹「注意休息」提醒（恢复 / 休息 / 拉伸 / 瑜伽 / 泡沫轴等不计入）。

### 4. ITRA 数据面板
- 展示跑者 **Performance Index**（当前 445）、等级（Intermediate 3）、World Top 排名等。
- 完赛数、总距离、总用时、总爬升、最长距离、最佳排名（含赛事名与日期）等统计。
- 含头像、ITRA 主页链接与数据更新时间；数据来自 `itra_data.json`，可定期更新。

### 5. 配色主题
- 提供两套主题：**狗狗黑**（默认，强调色柠檬黄）/ **喵喵粉**（强调色粉红）。
- 切换即时生效并记忆到本机，下次打开保持；**页脚背景色两套主题统一为珊瑚橙**。

### 6. 数据持久化与同步
- **本机优先**：所有改动先写入浏览器 `localStorage`（key `wamiao_state_v2`），刷新页面或重新部署都不会丢失。
- **跨设备同步**：连接 GitHub 后，可点「**上传到云端**」把本机完整状态推送到仓库 `state.json`；换设备后点「**从云端下载**」拉取（需登录且拥有仓库 Contents 写权限）。
- **网络容错**：若遇网络异常导致云端同步失败，本机数据不受影响；网络恢复后再次编辑或刷新即可自动补同步。

### 7. 其他实用能力
- **撤销上一步** / **恢复默认库**（训练库快照）。
- 分类筛选（**全部 / 路跑 / 越野 / 通用 / 交叉训练 / 游泳 / 骑行 / 比赛**）——同时筛选训练库列表与训练计划 / Takeaway 日历。
- **手机端响应式布局**：训练计划与 Takeaway 在移动端均按「左栏统计 / 日历在下」的方式展示，工具栏按钮在窄屏下自动换行可见。

## 使用

1. 打开上面的在线地址。
2. 点击右上角 **`log in`**，粘贴你自己的 **GitHub Fine-grained PAT**（仅限本仓库 `Contents: Read and write` 权限）登录。
3. 登录后可编辑训练计划与 Takeaway；改动自动保存到本机（`localStorage`）。
4. 跨设备同步：点「**上传到云端**」把本机状态推送至仓库 `state.json`；换设备后点「**从云端下载**」拉取。

> token 只保存在你本机浏览器（`localStorage`），不进源码、不写云端、不暴露给任何访客。

---

## 安全模型

- 站点为公开 Pages，数据任何人都可见（仅查看）。
- 编辑需「连接 GitHub」：用你自己的 PAT 登录，源码中**不含任何共享写凭据**。
- 加载时公开拉取 `state.json`，无需 token；保存时经你本机 token 写回仓库。

## 部署（站主）

本仓库为站点发布仓库，存放构建产物、运行数据与文档。源码在本地维护，通过部署脚本发布。

部署走 `deploy_rest.py` 的 GitHub Contents API：

1. 将 GitHub token 放入 `.deploy_token`（参考 `.deploy_token.example`，已被 `.gitignore` 忽略，绝不入库）。
2. 本地构建：`node node_modules/vite/bin/vite.js build`。
3. 部署：`python deploy_rest.py`。

> 每个正式版本都会打 Git Tag 并创建 GitHub Release（见下），可随时回退到对应版本的文件或重新部署该版本。
